# EBPM 設計

## 目的

ステーブルコイン助成金は、現金給付やクーポンと比べて
**「いつ・どこで・誰が・何を買ったか」が機械可読な形で残る** 点が最大の利点。
この特性を活かし、東京都が政策評価 (EBPM) を行えるダッシュボードを提供する。

## ロギングモデル

各購入トランザクションから、以下のレコードを `ebpm_events` テーブルに残す。

```
EBPMEvent {
  id                : UUID
  program_id        : プログラム ID
  ts                : 取引時刻 (UTC)
  jan               : 商品 JAN
  category          : 商品カテゴリ (家電/食品/医薬品...)
  store_pid         : 店舗の擬似 ID
  store_ward        : 区市町村
  citizen_pid       : 住民擬似 ID (HMAC)
  age_band          : 年齢階級 (10歳刻み: 0-9, 10-19, ...)
  gender            : 性別 (M/F/X)
  ward              : 居住区市町村
  qty               : 数量
  total_jpy         : 総額 (JPY)
  subsidy_jpy       : 助成金額
  citizen_pay_jpy   : 自己負担額
}
```

- 個票には**氏名・生年月日・住所そのもの**は出さない
- `age_band`, `gender`, `ward` の組合せで k-匿名性 (k ≥ 5) を満たすよう
  集計クエリ側で N <  5 のセルは「-」表示に丸める

## 提供 KPI

| 指標                       | 用途                                       |
|----------------------------|--------------------------------------------|
| 助成金消化率               | 予算がきちんと使われているか              |
| 補助 1 円あたりの自己負担   | レバレッジ効果 (経済波及)                 |
| 受給者カバレッジ            | 想定対象者のうち何 % が利用したか         |
| 商品カテゴリ別シェア        | 想定外品目への偏りがないか                |
| 区市町村別利用率            | 地理的不公平の検出                        |
| 時間帯別利用                | 在庫・物流計画                            |
| リピート率                  | 消費の継続性                              |

## ダッシュボード仕様 (`frontend/ebpm.html`)

- プログラム選択 → 4 つの主要カードを表示
  - 予算消化額 / 残額
  - 受給ユニーク住民数
  - 平均助成額 / 平均購入額
  - 平均レバレッジ (`citizen_pay / subsidy`)
- 4 つのクロス集計グラフ
  - 年齢階級 × 助成金額
  - 区市町村 × 利用件数
  - 商品カテゴリ × 助成金額
  - 日付 × 件数 (時系列)

## プライバシー保護

1. **擬似 ID 化**: マイナンバー由来 ID は `HMAC-SHA256(secret, maina_id)` で
   オフチェーン保管。元情報は復元不能。
2. **集計のみ公開**: API は集計値のみ返却。個票エンドポイントは内部監査ロール限定。
3. **k-匿名性**: 年齢×性別×区の組合せセル数 < 5 は丸める
4. **目的外利用禁止**: PBM トランザクションログは助成金監査・EBPM 集計以外には使用しない (規約)
