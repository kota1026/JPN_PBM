## 2. v2 の設計原則

> **「電源も通信も無い状況で、なりすまし防止 + 二重支給防止を担保する認証はどう設計するか」** から再出発。

3 層構造:

```
[Layer A] 個人デバイス: マイナンバーカード (Felica SE)
              ─ タンパー耐性 + monotonic counter
              ─ 平時に「今月のオフライン枠」を pre-stage
              ─ 受給者が常時携帯

[Layer E] 政府端末: 避難所のタブレット
              ─ 発電機 + 衛星通信
              ─ NFC リーダ内蔵、Felica の SE と通信
              ─ 公務員が運営

[Layer 紙] 二次救済: 紙 QR (CP-6a)
              ─ SE カード喪失 / 不携帯ケース
              ─ ECDSA 署名つき紙印刷
              ─ 避難所職員が手書き台帳に転記
```

---

## 3. 各層の役割

### Layer A: マイナンバーカード Felica SE

**前提**: 既に全国民に配布済 (普及率 90%+ 想定)、新規ハードウェア配布不要。

| 項目 | 内容 |
|------|------|
| ハードウェア | マイナンバーカードの Felica チップ (RC-S960、SE 内蔵) |
| 平時 prefund | 月初に「**今月のオフライン枠**」を SE に書込 (例 ¥10,000) |
| 災害時動作 | NFC リーダ (避難所端末) と通信、SE counter で残量管理 |
| 二重支給防止 | SE 内 monotonic counter (タンパー耐性) |
| 電源 | カード自体は不要 (リーダ側のみ) |
| バックアップ | カード喪失時は L 紙 で救済 |

**実装上の鍵**: 既存マイナポータル v2 OAuth flow に、「**SE への pre-stage 書込み権限**」を追加する必要あり。これは **JPKI Public Key Infrastructure** の API 拡張。

### Layer E: 避難所端末

**配備計画**: 全国 1.5 万指定避難所 + 約 5,000 LGU 庁舎 = **約 2 万台**

| 項目 | 内容 |
|------|------|
| ハードウェア | iPad Pro 級タブレット + NFC リーダ + 衛星通信 (Starlink mini) + 発電機 (5kVA) |
| 1 台当たりコスト | ~¥250,000 (ハードウェア) + ~¥100,000 (発電機) = ¥350,000 |
| 全国配備総額 | 約 ¥7B (一括) または ¥1.4B × 5 年 |
| 運営者 | 自治体職員 (避難所運営の延長) |
| 平時の用途 | 国民健康保険 / 各種証明書発行端末との **共用** で稼働率確保 |

**重要**: この投資は CP-6 専用 ではなく、**国民健康保険手続き / マイナンバー認証窓口** との **共用化** で justify。これにより自治体予算で正当化可能。

### Layer 紙 (CP-6a): 二次救済

**用途**:
- マイナンバーカード喪失/破損
- 避難所到達不可で **戸別訪問チーム** (民生委員 + DMAT) が現場で給付
- バッテリー切れ等で SE が読めない

**仕様**:
- ECDSA 署名済 QR 印刷紙 (耐水ラミネート)
- 月次配布 (オプトイン)
- 避難所/民生委員が手書き台帳記入 → 復旧後デジタル取込

## 4. データフロー (災害時)

### 4.1 平時 prefund (月初)

```
DSWD/TMG ──→ JPKI API ──→ 住民マイナンバーカード SE
                          月次オフライン枠 ¥10,000 書込
                          counter = 0 リセット
```

### 4.2 災害発生 → 給付

```
住民 (マイナカード持参) ──→ 避難所端末
                              NFC で SE 読取
                              counter ≤ 月次枠?
                              [✓] 給付物資配布
                              [✓] SE counter 更新
                              [✓] 端末ローカル DB に redemption 記録
                              [✓] 衛星経由で contract に送信 (即時 or 復旧後 batch)
```

### 4.3 戸別訪問 (高齢/乳児/移動困難世帯)

```
民生委員 + DMAT ──→ 訪問先世帯
                       紙 QR 受領 + 顔確認
                       手書き台帳記入
                       (復旧後にスキャン入力 → contract batch)
```

## 5. CP-1〜CP-7 整合性

| CP | v2 での担保 |
|----|------------|
| CP-1 (緊急停止) | 通常運用と同じ。governor.revokeProgram() |
| CP-2 (eligibility) | SE の事前 prefund + 月次枠が承認の証 |
| CP-3 (peg) | JPYC 通常運用 |
| CP-4 (privacy) | SE 内データは HMAC PID のみ、生マイナンバー不在 |
| CP-5 (二重支給) | **SE counter (機械的厳密) + on-chain consumed (二重防御)** |
| CP-6 (災害時) | **本 v2 の核** |
| CP-7 (cap) | 月次枠 = SE 上限 |

## 8. 残課題 (Round 19+)

1. **JPKI API での SE prefund 書込み権限**: 現状 JPKI は個人認証のみ、書込みは想定外。総務省と協議必要。
2. **避難所端末 共用化の制度設計**: 国民健康保険・自治体証明書発行端末との統合運用ルール
3. **Starlink mini を含む通信冗長化**: 衛星通信の常時接続コスト・許認可
4. **5 年計画の予算化**: 総事業費 ¥7-10B (2 万台 × ¥350-500K)
5. **マイナンバーカード未保持者 (高齢者中心、~10%)** への代替手段: 紙 QR + 戸別訪問の標準化

これらは政策・調達領域。技術設計としては本 v2 で完結。
