# JPN-PBM
## 東京都の助成金を「目的どおりに使える」お金にする

紙の助成券 → プログラム可能な JPYC へ。

加盟店レジでそのまま使えて、二重支給・目的外利用が物理的に起きない仕組み。

**2026-05 · 開発 11 ラウンド完了 · 提案書 v1.0**

## 1. 何が課題か (現状の助成金オペレーション)

東京都 23 区が **年 ¥640B** の助成金を紙ベースで配っています。

| 痛点 | 自治体 1 つあたりの年間コスト |
|------|------------------------------|
| 紙申請の受付・資格審査 (人手) | ¥120-240 M |
| 紛失・再発行の事務 | ¥8-15 M |
| 目的外利用 (例: 子育て券で酒を購入) | **配布額の 3-7%** |
| 重複支給 (複数プログラムの突合不能) | 配布額の 1-2% |
| 都議会への効果報告のラグ | 4-8 週間 |

→ **目的外漏れだけで 23 区合計 年 ¥32 B が静かに失われている。**

---

## 2. なぜ今までデジタル化できなかったのか

「QR 決済アプリ」では解決しません。理由:

- ❌ アプリ会社が事業撤退したら券が無効になる (持続性リスク)
- ❌ アプリ社のサーバが落ちると使えない (災害時に最も困る)
- ❌ 商品単位の制御 (この JAN コードのみ可) ができない
- ❌ 目的外利用は「あとで集計してわかる」だけ、その場で止められない
- ❌ 個人情報がアプリ社に蓄積される (個情法リスク)

JPN-PBM は **これらすべてに最初から答えを持って設計** しています。

---

## 3. 解決策 ─ PBM (Purpose-Bound Money) とは

<div class="lede">

「**使い道があらかじめプログラムされた円**」のことです。

</div>

```
通常の JPYC (¥1 = 1 JPYC):
  └─ 誰でも・どこでも・何にでも使える

PBM でラップした JPYC:
  ├─ 江東区在住・3 歳児がいる世帯
  ├─ 認定加盟店 (区が登録した育児用品店)
  ├─ 育児用品 JAN コード (おむつ・粉ミルク等)
  ├─ 期間内 (2026/4/1 - 2027/3/31)
  └─ 月 ¥10,000 まで
                    ↑ 5 つすべて満たさないと 1 円も動かない
```

ブロックチェーンの強制力で、**目的外利用が「あとで気づく」のではなく「最初から起きない」**。

## 4. 4 つの役割で動く

```
┌─────────────────┐    ┌─────────────────┐
│  ① 東京都・自治体 │ →  │  ② 住民 (マイナ)│
│  プログラム設計   │    │  受給資格を確認  │
│  予算ロック       │    │  PBM を受け取る │
└─────────────────┘    └────────┬────────┘
                                  │ QR を見せる
                                  ▼
┌─────────────────┐    ┌─────────────────┐
│  ④ EBPM 分析     │ ←  │  ③ 加盟店レジ   │
│  消化率 KPI      │    │  JAN を読み取り │
│  k-匿名で公開     │    │  対象なら自動補助 │
└─────────────────┘    └─────────────────┘
```

それぞれ Web 画面 (HTML) で **すぐ触れる動作デモ** が完成済みです。

## 5. ★ 災害時フォールバック (CP-6 v2) ─ 日本独自最適化

<div class="highlight">

**首都直下地震が発生し、ネットも電気も止まったら？**

通常のキャッシュレス決済はすべて止まります。
JPN-PBM は **オフラインのまま助成金を配布できる設計** です。

</div>

仕組み (8 ステップ):
1. 平時に都の governor が **ECDSA 署名** で「災害用 QR (1 ヶ月有効・住民/月/上限を内包)」を住民に事前配布
2. 認定加盟店リスト + governor 公開鍵を POS 端末に同期
3. **災害発生・ネット遮断**
4. 住民が QR 提示 → POS がローカルで署名検証 + nonce 重複検査 + cap 残高確認 (すべて**オフライン**)
5. POS が住民に物品支給 + 紙レシート発行 + 端末 SQLite に redemption を蓄積
6. **ネット復旧**
7. POS が蓄積バッチを `redeemBatch()` でチェーンに提出
8. オンチェーン側が ecrecover で再検証 + `consumed[pid][month]` で二重消費防止 + JPYC 払い出し

> 世界中で、能登半島地震 (2024) を経験した国・地域でこの仕組みを持つ自治体は **ありません**。
> 東京都が出せば、国際フォーラム (OECD / BIS / MAS) で日本の独自貢献になります。
>
> **詳細シーケンス・実装ファイル番地は `docs/cp6-offline-fallback.md` に記載。**

## 9. 個人情報・法令の整理

| 法律 | 対応 |
|------|------|
| **個人情報保護法 16 条** | マイナンバーは HMAC で擬似 ID 化、生 ID はチェーンに乗らない |
| **個人情報保護法 / 統計法** | EBPM 集計は **k-匿名性 (k=5)** を機械的に強制、5 人未満セルは抑制 |
| **資金決済法** | JPYC の既存 Type II ライセンスをそのまま利用、PBM は流通済 JPYC を**ロック**するのみ → 新たな発行行為なし |
| **電子帳簿保存法** | 全 state 変更が event log に記録、改ざん検知可能 |

→ **新法・特区指定は不要**。既存法令の枠内で運用可能なよう設計済み。
