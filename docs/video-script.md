# 動画用デモ手順書 (約 4 分想定)

東京都ステーブルコイン助成金プロジェクト向けの提出動画を撮るための
**台本 + 操作手順 + キャプション案**。1 テイクで撮り切れる構成にしてある。

---

## 事前準備 (録画ボタンを押す前に済ませる)

1. ブラウザを 1 枚開いておく (Chrome 等、ズーム 110% 推奨)
2. ターミナルで `cd backend && uvicorn app.main:app --port 8000` を起動
3. http://localhost:8000/ui/index.html を開いて **「デモデータをロード」を 1 回押しておく**
4. **山田太郎の pid をクリップボードにコピー** (`citizen.html` で MN-0001 で認証 → pid 表示される)
   - もしくは下のスニペットで取得:
     ```bash
     curl -s http://localhost:8000/wallet/citizen/$(curl -s -X POST http://localhost:8000/seed/load | python3 -c 'import sys,json; print(json.load(sys.stdin)["pid_map"]["MN-0001"])') | python3 -m json.tool
     ```
5. 録画ツール: **Loom / OBS / QuickTime** など、ブラウザ全画面 + マイク

> ⚠️ デモは UI だけで完結する。ターミナルは映さなくて OK。

## シーン構成 (合計 3 分 50 秒目標)

### Scene 0 — オープニング (10 秒)

> **画面**: トップ `/ui/index.html`
> **語り**: 「東京都ステーブルコイン助成金の MVP 実装『JPN PBM』のデモです。
> JPYC をラップした **Purpose Bound Money** で、JAN コードによる商品識別と、
> マイナンバーカード 4 情報による受給資格判定を組み合わせて
> 助成金が目的どおりに使われたことを保証します。」

**キャプション**: `JPN PBM — Purpose Bound Money on JPYC × JAN × マイナンバー`

---

### Scene 1 — 東京都が助成金プログラムを設計 (45 秒)

> **画面**: `/ui/tokyo.html` を開く

操作:
1. トレジャリー残高 (¥100,000,000) を見せる
2. プログラム一覧から `prog-eco-2026 省エネ家電購入支援` を指差し
3. 「新規プログラム作成」フォームに **空のサンプル** を入れる流れだけ見せる
   (実際にサブミットしなくて良い・既存 3 件で十分)

> **語り**: 「都の担当者は、対象 JAN コードの集合・助成率・住民 1 人あたり上限・
> 受給資格条件 (居住区・年齢・性別) をプログラムとして登録します。
> 予算分の JPYC は作成と同時にトレジャリーからエスクローされます。」

**キャプション**:
- `予算 ¥50,000,000 を JPYC でロック`
- `対象 JAN = 省エネエアコン / 冷蔵庫 / LED`
- `住民1人上限 ¥50,000 / 助成率 30%`

---

### Scene 2 — 住民がマイナ認証で PBM を受領 (50 秒)

> **画面**: `/ui/citizen.html`

操作:
1. デフォルトで MN-0001 (山田太郎・新宿区・70 歳・M) が入っている
2. 「マイナンバー認証」ボタンを押す
   → 擬似 ID (HMAC) が `badf24…` と表示される
3. 「② 受給可能な助成金プログラム」に **2 件**だけ表示される
   (子育てプログラムは年齢で自動除外される点を強調)
4. `prog-eco-2026` の「PBM を申請する」ボタン → アラート「PBM 発行 OK / 枠 ¥50,000」
5. 続いて `prog-senior-2026` も同様に申請
6. 「③ ウォレット残高」で **PBM 2 件保有** が見える

> **語り**: 「住民はマイナンバーカードをかざすと、4 情報がオフチェーンで HMAC 化され、
> 受給資格を満たすプログラムだけが提示されます。 35 歳の住民にはシニア向けプログラムは
> 表示されない、というロジックがここで効いています。
> ボタン 1 つで PBM トークン、つまり助成金枠が住民のウォレットに発行されます。」

**キャプション**:
- `4 情報 → HMAC で擬似 ID 化 (元情報は復元不可)`
- `ward / age で自動絞り込み`
- `PBM = JPYC を Purpose 付きでロックしたトークン`

---

### Scene 3 — 加盟店 POS で JAN 購入 → 助成金が自動アンラップ (60 秒)

> **画面**: `/ui/retailer.html`

操作:
1. 加盟店プルダウンを **ビック家電 新宿東口店** に
2. 住民 PID 入力欄に山田太郎の pid を貼り付け
3. JAN コードに `4901234567890` (省エネエアコン) を入力 → 「商品検索」を押すと
   `省エネ8畳エアコン EX-2025 / appliance.air_conditioner / ¥120,000` が表示
4. 「PBM 決済を実行」を押す
5. 結果カードに **合計 ¥120,000 / 助成 ¥36,000 / 自己負担 ¥84,000 / 助成率 30%** が出る

続けてもう一発、**対象外**を見せる:

6. JAN を `4934567890121` (おにぎり) に変更 → 商品検索 → ¥180
7. 決済実行 → **助成 ¥0 / 自己負担 ¥180**

> **語り**: 「加盟店の POS は JAN コードをスキャンするだけ。バックエンドは商品が
> どのプログラムの対象 JAN リストに含まれているかを照合し、住民の eligibility を
> 再確認した上で、PBM が JPYC にアンラップして店舗に流れます。
> 対象外商品は自動的に通常決済になり、助成は 0。**目的拘束**が強制されています。」

**キャプション**:
- `JAN ≠ 対象 → 助成 0 (Purpose 違反は通らない)`
- `PBM 残枠 ¥50,000 → ¥14,000 (=50000-36000)`
- `店舗は JPYC 全額を即時受領`

---

### Scene 4 — EBPM ダッシュボード (45 秒)

> **画面**: `/ui/ebpm.html`

操作:
1. プログラム選択は (全プログラム) のままサマリを見る
   - **取引件数 / 受給人数 / 助成金額 / 自己負担 / レバレッジ** の KPI が表示される
2. プログラムを `prog-eco-2026` に絞る → サマリと残予算が更新
3. 軸セレクタを `category` に → 商品カテゴリ別ブレイクダウン
4. 「ユニーク人数 5 未満は `-` に丸めています」のキャプション部分にズームイン

> **語り**: 「全取引が匿名化された 4 情報属性とともにロギングされ、政策担当者は
> リアルタイムでプログラムの **消化率** **レバレッジ** **受給者カバレッジ** を
> 可視化できます。年齢×性別×区のクロス集計で k 未満のセルは自動で丸められ、
> 個人特定リスクを抑えながら EBPM が成立します。」

**キャプション**:
- `レバレッジ = 自己負担 / 助成額 (経済波及の指標)`
- `k=5 未満は - に丸めて k-匿名性`
- `category × ward × age_band で多軸分析`

---

### Scene 5 — クロージング (20 秒)

> **画面**: トップに戻る or `contracts/PBM.sol` をエディタで一瞬映す

> **語り**: 「MVP の PBM ロジックは Solidity コントラクトと同等のステートマシンで、
> Polygon zkEVM 上の JPYC v2 にそのまま接続できる構造になっています。
> マイナポータル JPKI / 加盟店 POS SDK / 都税控除との連動が今後の拡張ポイントです。
> ありがとうございました。」

**キャプション**: `Next: JPYC v2 / JPKI / POS SDK 連携`

## トラブルシュート (撮影中の事故対策)

| 起きうる事象                          | 対処                                             |
|--------------------------------------|--------------------------------------------------|
| Scene 3 で「住民の JPYC 残高不足」    | `tokyo.html` の topup フォームで citizen に入金   |
| 受給可能プログラムが空                | seed が走っていない → トップで再ロード             |
| EBPM サマリが空                      | 購入が成立していない → Scene 3 をやり直し         |
| ブラウザに古い結果が残る             | リロード or `rm backend/jpn_pbm.db && uvicorn` 再起動 |
